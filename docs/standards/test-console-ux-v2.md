# FlowGate 测试台可用性 V2.0｜功能块 2 强制整改契约

> 版本：2026-11-06，**设计任务，尚未落地前端代码**。
> 已确认用户反馈：当前 Control 原生测试台虽然可请求接口，但**操作困难、缺少独立使用指南**。本文件优先于旧 `docs/standards/frontend-sync-rule.md` 中仅要求“五区功能齐全”的最低交付样式；仍坚持无框架、无 npm、纯原生 HTML/CSS/JS。

## 一、目前源码明确存在的问题

核对 `flowgate-control/src/main/resources/static/test-console/index.html`、`app.js` 和 `style.css` 后：
- 主要内容按 A/B/C/D/E 五区同屏铺开，用户首次打开面对大量字段，必须理解 JSON、版本 CAS、Scope 才能完成基础体验。
- “实际 HTTP 结果”只有页面底部**一个共享区域**，下一次操作会覆盖上一次结果；不易知道哪个按钮出错。
- `expectedVersion` 初始化为 `0`，发布成功后没有自动刷新当前版本、节点是否已生效或旧草稿状态，用户易遇到 409。
- “初始化公共 Demo 草稿”“私有草稿”“回滚”未解释其影响范围、是否覆盖或创建，以及确认前后的变化。
- 策略填写主要依赖手写 `parametersJson`；真正生效与仅入库配置不够直观。
- 网页顶部只有一句操作顺序，**没有可单独打开的逐步使用指南、异常处理与预期 HTTP 码对照**。

这些是静态代码和用户实际体验反馈可确认的设计问题；功能块 1 日志称浏览器测试通过，不等于新用户能独立使用。

## 二、目标：无需查 Java 源码也能完成最小演示

必须支持非项目作者在页面帮助和 `docs/guides/test-console-guide.md` 的指导下，完成以下五步：

1. **环境自检**：显示 Control、MySQL、Redis、Demo、Gateway 的独立探测结果；离线项有对应本地启动指令和检查地址。不显示未经验证的 “UP”。
2. **管理员登录**：展示当前登录角色与过期提示；未登录时控制台仍可看帮助和服务状态，但需凭证的操作禁用且说明原因。
3. **初始化 Demo 草稿**：清晰解释“只补缺失，不覆盖已存在，不自动发布”，确认后执行；展示实际创建与已存在的对象数量。
4. **发布并确认节点**：自动加载最新 `current.version` 为 expectedVersion，但如果本地草稿和远端变化存在冲突，提示用户**重新读取**，不自动静默重试 409。发布结果 `PERSISTED` 与节点 `appliedVersion` 明确分屏/分状态，不说发布就是应用。
5. **发起真实请求**：GET fast、POST echo、GET slow，查看状态、耗时、Request ID；私有 API 401/403/200、Caller 吊销/回滚留在“进阶验证”页签。明确“HTTP 429/503 在 Block2 策略生效后才可看到”。

## 三、页面结构（可用小组件，不造复杂 UI 库）

保持 `/test-console/` 唯一入口；推荐：
- **顶部状态条**：当前服务地址、依赖在线概览、当前已发布版本、当前 Gateway 节点应用版本，标明状态更新时间；提供“重新检查”按钮。
- **主区域：快速开始（默认打开）**：五步进度条 + 每一步的最小输入/操作/验证结果。**不能把所有原始 JSON 表单放在首屏**。
- **业务测试页签**：fast/echo/slow/私有 API、Caller Token 最小输入；一项请求有一张就地结果卡，便于同时比较 HTTP 状态。
- **配置管理页签**：服务/API/路由的中文表单和可读列表；“高级 JSON 编辑”放折叠区，保留完整旧功能。
- **策略与流控页签**：可选目标路由、策略类型、scope、参数、保存、绑定、发布、试跑；列出当下真实“已执行/未执行”，Block3 功能明确待开发。
- **版本与审计页签**：草稿未发布说明、发布历史与节点版本对照、回滚选择、最近审计记录。
- **帮助页签**：集成入门说明、请求码/常见错误解释、外链至仓库 Markdown 手册（如果页面访问无法直接打开仓库链接，至少将核心步骤内嵌，不依赖联网）。

窄屏单列；所有表单按钮采用可读中文动词（如“发送快速查询”“保存草稿”“发布新版本”），所有可执行操作均具备可访问 label，键盘 Tab 可到达，焦点、disabled 原因清晰。不要求华丽动画。

## 四、交互状态与防误操作

| 交互 | 用户可见约束 |
|---|---|
| 服务探测 | 控制面 HTTP 可访问不代表数据库/Redis 正常；未探测显示“未检查”，失败显示“离线/依赖不可用”，不能混为已通过 |
| 登录与凭证 | Token 只在 JS 内存和必要的密码输入框，不能存 localStorage/sessionStorage/cookie；刷新即失效，页面要说明 |
| 保存草稿 | 明确这是保存但**未发布**；提供查看草稿、变更后的实际 ID，不显示“已生效” |
| 发布 | 显示即将发布的最新 expectedVersion，执行前一次确认；HTTP 409 展示“版本已变化，请先刷新”及刷新入口 |
| 节点版本 | 显示 `PERSISTED` 和 `APPLIED` 的两个独立字段；未上报时展示“待应用”，不能用固定计时器推测成功 |
| 回滚 | 必须选具体历史版本，确认“生成新版本，不撤销草稿”，显示回滚前后版本及对私有路由/限流的影响 |
| 调用方创建/吊销 | 确认 Caller ID 和 Scope，签发 Token 一次性展示（默认掩码，可手动复制），吊销需确认不可逆影响 |
| 请求测试 | 每张结果卡展示操作、方法/不含秘密的 URL、HTTP 码、耗时、Request ID、解析后的 JSON/文本；提供安全复制按钮 |
| 结果历史 | 仅保留浏览器内存中最近 10 条**已清除 Token/密码/内部 Key 的摘要**；当前结果不被其他按钮直接覆盖；刷新清空 |
| 错误提示 | 400 输入错误、401 未认证、403 权限不足、404 路由不存在、409 版本冲突、429 限速、503 过载/依赖失败；需注明是哪一种，不要全显示“操作失败” |
| 按钮忙碌状态 | 发送中禁用同一个操作按钮并标明“执行中”；禁止误触重复发布、重复 Caller 创建或双重回滚 |

## 五、脚本结构与安全

- 继续原生 HTML/CSS/JavaScript，不引入 npm、Vue/React、Tailwind、外部 CDN、图表库、状态管理框架或新的服务进程。
- 允许把长 `app.js` 拆为 `api.js`（统一 fetch）、`state.js`（内存状态）、`ui.js`（页面渲染）、`app.js`（绑定交互）；若真实代码简单，保持少量文件即可，**不要为拆文件增加复杂工程结构**。
- API 请求/身份模型与 Block1 保持一致；不要直接在前端调用 `/internal/**`，不泄露 `FLOWGATE_INTERNAL_KEY`；不要把管理 Authorization 发往任意外域。
- 不渲染未经过 HTML 转义的远端数据到 `innerHTML`；动态文本优先 `textContent`，禁止把 JSON/错误直接当 HTML。
- 保留块 0/1 的全部能力及实际 HTTP 语义，不把“按下按钮”认作成功；发布和回滚以真实返回及节点生效状态为准。
- 只有明确的 RATE_LIMIT/CONCURRENCY 执行机制和真实请求验证通过，才把对应 UI 标为“已生效”；TIMEOUT/CIRCUIT_BREAKER 仍禁用并说明 Block3 开放。

## 六、最低可复测的体验验收

1. 在全新浏览器标签页打开测试台，不看 README 和 Java 源码，仅按页面提示完成首屏五步；路径从空数据库 V0 和已有版本 Vn 各跑一次。
2. 停用 Redis/MySQL/Control 中任一依赖，检查页面对应离线提示和修复说明，恢复后可手动重试；不暴露密码和内部 Key。
3. 用 VIEWER 登录，写按钮禁用且说明角色限制；用 OPERATOR 能保存/发布但不能建 Caller；用 ADMIN 可建/撤销。
4. 演示一次成功发布和一次 409 冲突：不自动强行覆盖其他管理员发布的版本；节点 applied 状态需真实显示。
5. 保存已有策略后，用户能分辨“仅草稿”“已发布但未应用”“已应用/规则执行中”，并能看到 429 或 503 真实拒绝。
6. 浏览器 Network/源码排查无明文凭证落盘、外部 API、未知 CDN；在 1280px 与窄屏视口基本可操作。
7. 更新使用指南，至少附带一条从启动到打开网页、发布、测试、回滚的**具体命令和点击路径**；若页面行为变更，指南同次更新。
