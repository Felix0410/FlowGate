# FlowGate V1.1 管理工作台 UX 重构设计（待实现）

> 设计日期：2026-11-09。基于 `feat/v11-console-unslop`（a02e68a），供本地 Codex 执行与负责人手动验收。**本文是设计任务，不表示 UI 已经修改或验收通过。** 不合并 main，不推进 V11-D。
>
> 约束：现有 Spring MVC 静态资源 + 原生 HTML/CSS/ES Modules；不引入 npm、Vue/React、UI 库、CDN、数据库迁移、新微服务；不改变 Gateway、配额、计量、Kafka、发布与审计的后端语义。保留 `/test-console/` 为开发验收工具。

## 1. 基于源码的实际问题

检查 `console/index.html`、`app.js`、`style.css`、`openapi-business.js`、`quota.js`、`usage.js`、`governance.js` 后发现：

1. `app.js/views` 在侧边栏平铺 **20 个入口、7 个文字组**。客户、应用、套餐、订阅、余额/账本、用量、异步事件和对账各自独立，缺少“客户→应用→订阅→配额→用量”业务上下文。
2. 现有侧栏白底、灰字、13px 链接，组名 12px 常规字重；当前选中只用浅蓝底和 2px 竖线。导航与正文同为白灰，主次层级不足。
3. 登录页有较大的口号与三段介绍；工作台在有真实业务数据时依然展示“开始接入一个API”的固定教学步骤；几乎每页 `heading` 再重复一次完整业务流程、限制或技术背景。这是开发说明书，不是高频工作台。
4. 目前导航 `href="#key"` 的点击默认行为被 `preventDefault` 拦截，而 `navigate` 不同步地址；前进/后退、刷新后的页面恢复、分享非敏感业务页链接不能按普通后台预期工作。
5. 页面间筛选与目标选择没有成体系传递；例如应用页按客户筛选、订阅页按应用筛选、配额账本查询也按应用，但需要重新寻找目标，操作链过长。
6. `/console/` 已有真实权限、发布CAS409、节点心跳、APP凭证、quota ledger、异步事件与对账等能力；**不是缺功能**，不要为了改版重建后端或把真状态改成静态演示卡。

## 2. 交互总原则

- **以用户任务组织页面，不以Controller/数据表数量组织菜单**。侧栏只放高频的业务域；页面内用 Tab；对象详情内展示相关资源并提供带上下文的跳转。
- **真实工作台**：展示“我当前管理什么、有什么异常、下一步该做什么”，不展示“我们是谁、每一步都有依据”之类宣言。
- **单页一个主操作**：列表页“新建”，详情页“编辑/下一步”择主；危险操作放次级区域并确认。按钮名称明确对象。
- **默认简洁，高级按需**：普通界面使用业务中文；原始ID、HTTP字段、Schema/JSON、Kafka专业状态解释放可展开技术详情和帮助页。涉及真实风险的 401/403/409/429/503 和异步状态不能隐去事实。
- **保存 ≠ 发布 ≠ 节点应用**。任何一处文案均不能偷换，不允许假差异预览、虚构指标、伪造零值。
- **少改变技术栈**：重排视图与复用现有查询；必须新增后端接口时先单独说明、默认不新增。

## 3. 新侧边栏：20 个入口 → 7 个一级业务入口

```text
FlowGate
─────────────────────────
工作台
API 接入
客户业务
治理策略
用量与对账
发布中心
运行监控
─────────────────────────
帮助中心
开发验证（次级 /test-console/）
当前角色 · 退出登录
```

| 一级入口 | 页面内部二级 Tab 或详情 | 对应原功能 | 默认页目标 |
|---|---|---|---|
| 工作台 | 概览；仅首次空数据时显示“开始接入”引导 | dashboard | 版本/网关、异常/待处理、业务入口 |
| API 接入 | 服务 / API / 路由；在服务/API详情查看关联对象 | services/apis/routes | 管理入口、路径、路由的完整链 |
| 客户业务 | 客户 / 应用 / 套餐 / 订阅；应用详情含凭证操作 | developers/apps/plans/subscriptions | 客户→应用→订阅可连续操作 |
| 治理策略 | 限速 / 并发 / 故障保护 / 计量规则 | rate/concurrency/protection/quota-policy | 选择目标后配置规则 |
| 用量与对账 | 余额与账本 / 用量统计 / 对账结果 | quota/usage/reconciliation | 按应用+UTC区间连续追踪 |
| 发布中心 | 当前版本 / 发布 / 历史 / 节点应用 | releases | 草稿→发布→已应用 |
| 运行监控 | 网关节点 / 异步事件 / 操作审计 / 调用方（独立管理子 Tab） | monitoring/async-events/audits/callers | 查故障、处理事件与凭证治理 |

> “调用方管理”属于旧Caller凭证而非V1.1 APP凭证，不得混在应用详情中；保留其独立真实入口，可在运行监控中用“访问凭证”子Tab明确区分，也可在后台“安全与审计”二级入口，取实现最易理解且不多造一级菜单的方案。API应用凭证必须留在应用详情。

导航规则：
- 一级最多 7 项，标签 2–5 个汉字优先；不再显示 20 条平铺菜单，也不需要常驻侧栏搜索框（如实际用户验证有需要可补）。
- 选中一级必须有显著底色、白色/高对比文字、标识线；一级分组与页内 Tab 形成两层明确区分。不能通过只改变文字颜色展示选中。
- 当前业务页只显示本页相关 Tab，不在别的组露出同一功能。
- 左侧固定；内容滚动独立。小屏侧栏抽屉、Tab 可水平滚动且明确可滚动，键盘/ESC/焦点仍可用。

## 4. 关键页面定义

### 4.1 工作台：操作态而非新手教程

登录后首屏建议结构：

```text
工作台                                     [刷新]
已发布 Vxx · 网关已应用 n/m · 最近读取时间
[需处理问题 n] [客户/应用 n] [API n] [当月配额状态（仅可从真实接口取数时）]
待处理                             近期操作（真实审计，若无法查则不展示）
- 节点滞后 / 发布未确认 / 事件积压
业务快捷入口：创建API / 创建应用 / 配置策略 / 发布
```

- 真实异常优先；若没有已确认的待处理数据，显示“暂无已发现的问题（最后检查时间）”，不可断言系统绝对无故障。
- “开始接入一个API”四步向导 **仅在首次空目录且已登录、核心查询成功时显示**；已有API或服务时不重复教学。
- 首页保留必要健康信息，但依赖状态不应重复占据大块首屏；按使用频率置于底部或可展开面板。
- 不新增无来源日活、收入、成功率、趋势图表。

### 4.2 API 接入：从服务到真实路由

- 服务列表，点击服务名进入详情，能查看其 API（真实API列表本地过滤）、进入具体 API，再查看关联路由；直接新建 API 时预选当前服务。
- API详情为“基础信息 / 关联路由 / 保护规则（若能真实判定关联）”。无实际查询或匹配依据时不展示伪关联；改为跳转策略页并带目标。
- 维护旧服务、API、路由创建/编辑完整PUT、草稿提示与发布入口；不伪造删除能力。

### 4.3 客户业务：对象详情驱动

- “客户列表 → 客户详情 → 该客户应用列表 → 应用详情”是主链。应用详情分区：“应用信息 / 凭证（单次明文领取） / 订阅 / 配额与用量”。
- 应用“查看配额”“查看用量”“新增订阅”按钮直接带入该 `applicationId` 到对应页查询，返回时保留前一个业务上下文；不得将凭证值写入URL/历史/缓存。
- 套餐、订阅仍可通过页内 Tab 直接管理；订阅只允许创建和查询，套餐额度创建后不可编辑；当前/次月排队不强行显示不存在的变更入口。
- 旧Caller和APP凭证属于不同身份体系，文案必须区分；APP凭证按现有一次性展示/撤销语义，离页清除。

### 4.4 治理策略：一个页内的规则管理

- 四个 Tab：限速、并发、故障保护、计量规则，保留各自真实参数、绑定目标与权限。
- 顶部统一：搜索、状态筛选、新建规则。打开表单时先选“保护对象”再设置该规则参数，参数帮助仅出现于对应输入字段。
- 保存后标“草稿已保存，发布后生效”；本次导航状态与筛选不被重置。历史绑定只读、不支持移动/删除时不制造对应按钮。

### 4.5 用量与对账：一次筛选，多种视图

- 共用应用和 UTC 时间范围筛选，保留在页面内部三 Tab 切换；余额与账本视图按现有月度契约，日报/对账按现有UTC日契约分别转换，不伪造可比时间尺度。
- “余额”权威来自MySQL，“用量”来自异步读模型，“对账”可能 PENDING/MISMATCH/INTEGRITY_GAP；三者不可在一张卡上混成单一实时指标。
- 异步事件诊断/补投置于运行监控，不让普通查询用户先看到Broker/Lease/Poison术语。

### 4.6 发布中心 / 运行监控

- 发布中心页面上方突出“保存草稿 / 已发布版本 / 节点实际应用”三阶段真实状态，下面才是操作按钮、版本历史、回滚确认。
- 运行监控默认显示网关/节点异常；“异步事件”是操作分区，FAILED重试与SENT未消费补投必须保持语义不同及二次确认；“审计”为只读。
- 旧Caller凭证区保留，但不可误认为V1.1 APP凭证，不新增全量Caller列表假数据。

## 5. 视觉规范（重点解决侧栏区分度）

- 建议深色侧栏背景 `#17212F`、导航文字 `#D9E2EC`、标题 `#9EACC0`；选中背景 `#274366`、文字 `#FFFFFF`、左侧蓝色指示。具体色值由浏览器对比度验证，可微调，但至少普通文字 4.5:1、较大文字 3:1，状态不只靠颜色表达。
- 内容区域仍为浅灰 `#F7F8FA` + 白色卡片。顶栏以“当前业务名称 / 发布与节点状态 / 操作员+退出”优先，不重复“本机/FlowGate/工作台”三重标识。
- 一级导航行高 40–44px、文字 14px/500；组标题无需常驻。页内 Tab 14px，选中用线条+粗细+背景/对比度两种以上信号。
- 各业务页主按钮只保留一个高权重按钮，其他为次级/文本；紧急撤销等危险操作保持确认。
- 图标可不做；如加图标必须同一线宽/尺寸且本地合法资源，不准 emoji、Logo墙、渐变或装饰仪表盘。
- 表格行可点名称进入详情；操作列只留“查看/更多”，细节行为在详情页。密集列表优先可读性和排序/筛选。
- 1280px需侧边栏与正文对比明显；375px抽屉、表格横向滚动、对话框全宽近似、无横向整页溢出；保留键盘焦点环。

## 6. 文案“去宣传化”硬规范

删除或移出日常主界面的实例：
- 登录“大字口号：接入、治理、发布，每一步都有依据”：改为“登录 FlowGate”+账号/密码/错误状态+指南链接；必要的临时环境说明放登录表单下小字。
- 固定三步流程、反复出现“客户→应用→套餐→订阅→凭证→计量→配额”的页面说明：变成按字段上下文帮助、首次空数据提示、指南详细章节。
- 页脚重复“FlowGate · API治理工作台”和重复指南：删除多余页脚文案，保留一处可达帮助。
- 成功时不写“恭喜”“开启xx旅程”“每一步都有依据”；使用“已保存草稿”“凭证已撤销”“当前网关2/3已应用”。
- 只有异常、不可逆动作、不可见的异步延迟和未发布等**影响决策的事实**值得在页首显示提示；普通技术细节默认放详情或帮助。

## 7. 导航状态与安全契约

- URL采用同源 hash 路由（如 `#business/apps?id=123&tab=subscriptions`）或最小 History API 实现；实现者选择一种，确保浏览器前进/后退和刷新后再次登录可恢复**非敏感页面**，未知路由回到工作台。
- 地址中禁止任何账号密码、管理Token、APP Token、Caller Token、密钥、完整原始管理响应。
- 在当前Tab从列表进入详情、返回列表时保留查询/筛选/当前页；切换到配额查询应预选从应用详情带来的ID；退出登录清除会话、DOM中的一次性回执与敏感临时数据。
- 全部权限仍由后端决定，前端按 ADMIN / OPERATOR / VIEWER 提示可操作状态；不要通过藏按钮当作安全策略。
- 旧 Control API 原样复用。任何辅助关联如果接口缺失，仅在客户端根据**已读完整集合**可验证地计算，否则展示“暂无法确认”或跳转筛选；不得伪造当前状态。

## 9. 严格验收

自动化：
1. 原V1+V1.1产品/授权/异步用量/配额/对账测试仍通过；`/test-console/` 仍可用，`/console/` 静态资源真实200。
2. 7个一级导航入口、20项旧功能在对应Tab/详情中均可抵达；键盘Tab/Escape/Enter与焦点回归正常，375/1280不横向溢出。
3. 保存草稿与发布/节点应用严格区分；409不自动重试；FAILED和SENT补投语义区分；敏感回执离页即清。
4. 浏览器前进/后退、详情直达、登录后恢复非敏感页面、旧地址/无效地址回退均正确。
5. 无假数据、无在报表加载失败时显示0、无未知状态被涂绿；真实API调用和RBAC维持。
6. 不在本地/CI对用户数据库做初始化、清理或迁移；真实HTTP用隔离环境。

负责人手测（必须实际完成并记录，脚本不能代替）：
- 1280px：不看帮助，能直接找到“客户→应用→订阅→签发凭证”和“API→规则→发布→节点确认”。
- 从一个应用详情直接查它的配额、用量、对账；不需要再次手工输入应用ID。
- 在侧栏上一眼辨认当前模块与相邻模块；白天普通亮度下，次级文字可读。
- 登录页和首页不再像宣传官网或“功能介绍页”；有数据时首页不反复展示四步教学。
- 375px可完成主要流程，抽屉/Tab不遮住操作或造成横向整页溢出。
- VIEWER/OPERATOR真实权限、报错、空状态、故障恢复可理解。

**保留事项**：原V11-D验收、性能、SQL优化没有因本设计而自动完成；本次只是UX专属工作，合并/发布需要负责人另行授权。
