# FlowGate V1｜产品管理后台重设计与落地契约

> 2026-11-06。负责人反馈：当前“前端乱七八糟、只有开发者看得懂”，**要求 V1 正式交付的是可正常使用的产品后台，不是堆了业务接口按钮的测试台**。
> **最高优先级**：本产品化任务是 Block4 正式全量测试之前的 P0 阻断条件。该任务已获得负责人明确需求授权，但本文只是设计，不表示新产品页已经完整实现。
> 目标入口：`http://127.0.0.1:8081/console/`。旧 `/test-console/` 仅保留为开发/验收工具，不再向普通管理员推荐。
> 技术：复用 Control Spring MVC 静态资源，**原生 HTML + CSS + 少量模块化 JavaScript**，不引入 npm、React/Vue、Tailwind、组件库、外部 CDN、新服务或数据库。初版以用户任务和交互正确性胜过复杂视觉特效。

## 0. 为什么旧页面必须重做，而不是换颜色

阅读 `flowgate-control/src/main/resources/static/test-console/index.html`（约21KB）及 `app.js`（约24KB）后，已确认：

1. 同一导航混放环境探测、HTTP 调试、Caller Token、目录 JSON、发布回滚、策略、故障实验、帮助和验收指标，普通操作者不知道从哪里开始；
2. “服务/API与发布”一个页面同时执行多对象创建、版本发布、历史与回滚；错误操作成本高，**业务对象未分层**；
3. 新建/修改依赖“先读取ID、修改完整JSON、再自己选择绑定对象”而不是列表→详情→操作的产品流程；
4. 真实 HTTP 请求记录和测试按钮占据业务主要区域；超时/熔断的实验场景与日常策略配置混用；
5. 页面缺少稳定的业务状态层级、明确主次按钮、空状态、可检索数据表、表单校验提示、错误恢复入口；50段输入说明和14章指南虽充分，却意味着界面本身未表达任务。
6. 单页全部按钮由一个大 `app.js` 绑定，依赖 DOM ID 和浮动上下文，不利于产品级权限一致性和视图维护。

**结论**：新建专门的产品管理入口，不在旧测试台上继续堆十几层折叠面板；原实验功能保留在 `/test-console/`，不做不必要的后端重构。

## 1. 产品定位、用户和一次成功路径

**定位**：FlowGate 是供系统管理员、运营人员管理 API 接入与治理的**内部运维管理平台**。不是面向 API 消费者的商业官网，也不是后台接口调试器。

- **ADMIN**：完整业务管理、Caller 凭证创建与吊销、发布回滚；
- **OPERATOR**：服务/API/路由配置、策略、发布与回滚，不能创建/吊销 Caller；
- **VIEWER**：查看资源、版本、节点、指标/审计；所有修改按钮不可执行并解释权限；
- **首次体验用户**：可能没有 Demo 配置或已有草稿，页面能提示下一步，而不是抛出大 JSON。

**最短关键路径**：登录 → 工作台看到版本/节点/依赖 → 服务/API 新建或选择已有 → 配置路由/策略 → 保存草稿 → 到“发布中心”确认 diff/当前版本（**无后端 diff API 则明确“没有差异预览”，只显示有来源的当前配置摘要**） → 发布 → 查看真实节点 appliedVersion → 回到 API 列表看到发布状态 → 进入开发工具做测试（可选）。

用户完成日常操作**不需要**理解 `expectedVersion`、`targetId`、JSON Schema、`PENDING_BLOCK3`、`CIRCUITBREAKER_EXECUTION_EXCEPTION_ATTR` 等源码概念；只有“高级详情”可以显示稳定 ID、HTTP code、Request ID 和调试信息。

## 2. 信息架构：左侧导航 + 顶部工作状态

```text
FlowGate · API 治理平台
├─ 工作台（首页）
│   ├─ 服务/API/路由/策略数量（来自真实列表）
│   ├─ 当前已发布版本、节点应用进度（真实节点状态）
│   ├─ Control/MySQL/Redis/Demo健康状况（实际探测）
│   ├─ 待处理提示（节点滞后/服务故障/未登录；不猜“有未发布修改”）
│   └─ 快速操作：接入服务 / 新建 API / 配置策略 / 发布变更
├─ 接入管理
│   ├─ 服务管理：列表/搜索/创建/编辑/启停（不支持删除则不显示删除按钮）
│   ├─ API 管理：HTTP方法、入口、上游路径、公开/授权/Scope、所属服务；列表/新建/编辑/详情
│   └─ 路由管理：稳定routeId、关联API、优先级、启停、发布状态；列表/新建/编辑
├─ 流量治理
│   ├─ 限速规则：容量/补充速率、作用范围、目标、启停
│   ├─ 并发规则：本机在途上限、范围/目标
│   └─ 故障保护：超时/熔断/GET静态降级，规则列表与可编辑表单
├─ 发布中心
│   ├─ 当前持久化版本 + 节点应用版本 + 心跳
│   ├─ 发布当前草稿（读当前version作为CAS；409绝不自动重试）
│   ├─ 历史记录、详情和回滚确认（回滚产生新版本）
│   └─ 状态含义：草稿已保存、配置已发布、节点已应用、节点滞后
├─ 调用方管理（只有ADMIN可创建/撤销，其余角色只按后端权限读）
│   ├─ 创建Caller/Scope/一次性Token领取
│   └─ 吊销Caller（确认不可逆）；没有查询API时不伪造调用方列表
├─ 运行监控
│   ├─ 网关节点 ONLINE/STALE/未知、applied版本
│   ├─ 熔断状态 CLOSED/OPEN/HALF_OPEN/未知（最近一次上报）
│   ├─ Actuator低基数指标（仅真实接口，缺少数据时写“暂无数据”）
│   └─ 审计记录（只读、分页；不包含密钥）
└─ 辅助入口（置底）
    ├─ 帮助中心（按页面就地帮助 + 完整中文指南）
    └─ 开发/验收工具 → /test-console/（明确这是开发者工具）
```

不设置单独“环境状态”“HTTP 请求测试”“最近10次结果”为主导航；环境是工作台的一块信息，操作结果在对应表单/页面就地反馈，HTTP测试进开发工具。

## 3. 视觉与组件规范（必须真的在浏览器里实现）

### 3.1 整体布局

- 登录前：独立登录页面，左侧品牌与 2~3 条平台能力，右侧居中的登录卡。无需预登录加载一堆禁用按钮；保留依赖状态/帮助入口。
- 登录后：左侧 **228–248px 深色稳重导航**（产品Logo、当前产品、栏目分组、选中项、底部角色/退出/帮助）；顶部 **64px 白色状态栏**（当前页名称、环境、本机节点、已发布Vn、操作员角色和刷新）；内容区域淡灰背景 + 白色卡片，最大宽度 1480px。
- 桌面内容：面包屑 + 页面标题 + 简短说明 + **一个主要操作按钮**；下面是概览指标/操作卡/真实数据表；表单使用右侧抽屉或居中对话框，不整页堆字段。
- 平板 768–1100px：导航可折叠；小于 768px 抽屉式导航、内容单列、表格可横向滚动（不可截断按钮），表单自动单列。320px仍能到达主要操作。
- 不把漂亮的“离线/已生效”标签硬编码为绿；所有状态都来自本机实际接口返回并带更新时间。

### 3.2 视觉 Token（可用 CSS 变量，避免到处重复魔法数字）

| 语义 | 建议值 | 目的 |
|---|---|---|
| 品牌主色 | `#2563EB` | 主按钮/当前导航 |
| 深色侧边栏 | `#111827` | 稳重企业后台 |
| 页面背景 | `#F6F8FC` | 与白色工作卡分层 |
| 主要文字 | `#111827` | 清晰可读 |
| 次要文字 | `#667085` | 元信息 |
| 分隔线 | `#E5E7EB` | 轻薄稳定 |
| 成功/警告/故障 | `#15803D` / `#B45309` / `#B91C1C` | 实际状态语义；图标和文字同现，不只靠颜色 |
| 圆角 | 10–12px | 卡片与输入一致 |
| 字号 | 14px正文、20–24px页面标题、12px辅助 | 不使用巨大 Header 占首屏 |
| 行高/间距 | 1.5 / 8px基础间距 | 形成严格层级 |

允许系统字体、内置 SVG/Lucide **如需图标必须随仓库有合法来源**；不要引入远程字体或图标CDN，宁可使用简单 CSS 图形/文字图标。无复杂动画；焦点清晰，减少运动偏好支持。

### 3.3 一组共享业务组件

- `AppShell`：侧边导航/顶部状态/主内容；按钮有主次危险层级；
- `StatCard`：真实数量+单位+状态时间；没读到显示“—/未读取”，不写0冒充真实零；
- `DataTable`：列标题、搜索、空状态、加载中、错误+重试、每行“查看/编辑”；支持小量本地过滤，不能假装服务端分页；
- `EntityDrawer`：新增/编辑表单，复用后端完整PUT契约，必须从真实记录回填全部字段；不做隐式部分PATCH；打开/关闭/取消不意外保存；
- `StatusTag`：DRAFT / PERSISTED / APPLIED / STALE / OPEN 只解释真实状态来源，不造“全部已应用”假数据；
- `ConfirmDialog`：发布、回滚、吊销（详细显示对象/目标/影响）；
- `InlineNotice`：验证错误/权限/409冲突在字段或当前页面提示且带下一步；
- `EmptyState`：没有服务/API/规则时一键创建；无权限、无服务、网络异常三种文案分开；
- `DetailsPanel`：技术字段（HTTP、原始JSON、Request ID、revision）放“查看技术详情”，不在主操作区域。

**禁止**：仅把原 HTML 套个侧边栏、把所有功能继续集中一个巨型表单、纯展示的假统计卡、按钮点击不真正请求、修改目标但后端未保存、无依据说“规则已生效”。

## 4. 页面级业务契约（允许把原生JS拆文件，不加前端框架）

### P0：工作台和导航

- 不登录也能看登录页面/离线帮助；登录后 `GET /status`、`GET /admin/{services,apis,routes,policies}`、`GET /admin/releases/current`、`GET /admin/nodes` 生成真实数量与状态。
- 顶部显示“发布版本 Vx / 节点 y/n 已应用”，**仅**当节点实际版本、心跳ONLINE且有真实回应时显示一致；未查询标“未获取”。
- 点击数据卡可导航至对应列表，所有需要写的功能按角色禁用，直接请求也由原后端校验。
- 后端异常要有可重试按钮，不能只显示一个 JSON 或空白页。

### P0：目录真实 CRUD（目前没有 DELETE API）

- 服务：列表列 `名称、代码、上游地址、启用状态、操作`；新建/编辑表单支持 `code,name,upstreamUri,enabled`。
- API：列 `HTTP方法、入口路径、关联服务、权限、启用状态、操作`；表单支持 `serviceId,method,publicPath,upstreamPath,isPublic,requiredScope,enabled`；私有API必须设置合法 Scope。
- 路由：列 `routeId、关联API、优先级、启用状态、操作`；表单支持 `apiId,routeId,priority,enabled`。
- 编辑必须先取真记录再**完整 PUT**，不能丢失未在界面显示的字段；若后端支持字段有限，显示只读字段而不造更改操作。
- 后端 PUT/POST 均只保存草稿，保存成功后显示“草稿已保存，尚未发布”，提供跳转发布中心。

### P0：治理策略

- 流量治理的速率/并发/超时/熔断使用**分类型表单**，用户先选“要保护的服务/API/路由”，后填该类型真实参数；把 scope、targetId 作为界面内部映射，不要求用户填数字ID。
- 参数沿用现有契约：RATE_LIMIT `capacity/refillPerSecond`；CONCURRENCY `maxConcurrent`；TIMEOUT `timeoutMs`；CB `failureRateThreshold/slidingWindowSize/minimumNumberOfCalls/waitDurationMs/fallbackMode`。
- 规则列表展示名称、策略类型、作用范围、目标名称、参数摘要、已启用草稿状态、操作；**只有确知后端绑定事实才能显示当前目标**。
- **已确认的 API 空缺**：`CatalogController` 仅提供 `POST /admin/policies/{id}/bindings`，没有正式的绑定查询。若真实 UI 要显示/编辑已有策略绑定，需要最小增量只读查询 `GET /admin/policies/{id}/bindings`（建议 ADMIN/OPERATOR/VIEWER 都可读，遵循现有RBAC），返回 `bindingId,policyId,targetType,targetId,targetLabel,targetRouteId` 中实际可取得字段。**不擅自新增绑定删除/移动API**；已有绑定只读且不能伪造更换目标。无法安全新增接口则策略编辑显示“绑定对象仅支持查看发布配置，暂不能在此更改”，需在验收中明确限制，不能默默隐藏。
- GET降级仅允许 GET 的路由; POST/PUT 不允许假成功。策略与 HTTP生效要等发布/节点APPLIED之后；“启用”不等于立刻上线。

### P0：发布中心

- `GET /admin/releases/current`、`GET /admin/releases`、`GET /admin/nodes` 真实读取；版本比较 `appliedVersion==published.version` 且ONLINE才显示已同步。
- 发布前显示**目标版本=当前版本+1、影响范围“全套当前草稿”、CAS确认**；把 expectedVersion 按真实读取结果自动提供给后端，遇409只提示刷新版本和检查变更，**不能自动重发/覆盖**。
- 历史版本列表有“查看”和“回滚到此版本”动作；回滚二次确认，回滚后实际产生更大的 Vn+1。禁止把已发布历史当成可修改草稿。
- 原后端没有“待发布差异”只读接口，首版不得显示具体新增/变更数量或默认“无待发布变更”；可以写“草稿与已发布版本差异需查看目录和历史”。

### P1：调用方、监控、审计、开发工具

- Caller 创建、Scope、签发Token一次性领取/遮罩、吊销；安全退出清理，ADMIN-only写操作；无Caller列表API时不显示假列表。
- 监控/节点表、CB最近状态、指标，空时提示“无样本/未获得”，后端Actuator访问受限不改变。
- 审计从 `GET /admin/audits?limit=...` 读取并可追加分页；无需在业务首页显示 SQL/HTTP原始错误体。
- 保留开发入口 `/test-console/`，文字明确为“开发与功能验证”；默认不会自动请求演示故障API、执行压测或持久化凭证。

## 5. 前端实现结构（尽量小，不造前端脚手架）

```text
flowgate-control/src/main/resources/static/
├── console/
│   ├── index.html           # 登录态、壳布局、页面挂载与访问性语义
│   ├── style.css            # CSS变量、响应式布局、卡片/表格/抽屉/通知
│   ├── api.js               # 管理请求、错误归一化、Token只存在内存
│   ├── app.js               # 页面导航/顶层状态/权限/视图刷新
│   ├── catalog.js           # 服务/API/路由CRUD与列表/表单
│   ├── governance.js        # 四类策略及真实绑定
│   └── operations.js        # 发布回滚、Caller、监控与审计
└── test-console/            # 保留开发HTTP与故障实验，不把旧代码删掉
```

模块通过原生浏览器 ES modules `<script type="module">`，无需Node/npm/Vite打包；纯JS文件不机械拆出每个按钮。页面保留一份顶层内存会话状态，通过小型 `api.js` 显式传 Token（可用模块作用域闭包），刷新清空，**无 localStorage/sessionStorage/cookie**。安全渲染尽量 `createElement`+`textContent`，禁止直接渲染不可信 `innerHTML` 和外部模板注入。

## 6. 验收脚本与用户实际体验

**自动化最低门槛**：
1. `/console/` 与 `/console/style.css`、JS 模块真实 HTTP 200，`/test-console/` 仍200；
2. 没有登录时页面不展示管理对象数据/Token，打开登录页面和帮助可正常使用；
3. ADMIN/OPERATOR/VIEWER 三角色后端真403和界面按钮一致；
4. 新建→编辑完整回填→保存草稿→发布→节点应用→回滚，在 UI 上有清晰各阶段反馈；控制台无需填JSON/内部ID；
5. API列表空状态、新建/编辑、私有Scope、策略参数校验和已有绑定只读、409并发冲突、网络失败重试；
6. Token仅内存、敏感响应脱敏、API只向同源管理与固定loopback Gateway；无外域CDN；
7. 1280px和375px视口、键盘Tab/ESC/焦点、aria-label/表单错误、色彩对比、屏幕阅读顺序基本合格；
8. 原 `block2-console-test.js` / `block3-console-test.js` 不回归；新增产品控制台 JS 契约测试 + 三 JVM 的真实 HTTP 简短验证。

**负责人验收（Codex不能代替）**：
- 首次登录后不读手册，5分钟内能够找到“创建API、绑定规则、发布”路径；时间目标只作体验观察，不装作自动化指标。
- 非开发者能从首页找到各对象及当前生效情况，完成一项策略并知道为什么“保存成功但还没生效”。
- 页面上不存在必须手写原始JSON才能完成最常见日常管理操作；高级调试在旧工具页面。
- 发现任何“修改没有真正持久化”或“错误版已生效”属于阻断错误，不能仅美化 UI。

## 7. Codex严格实施顺序

1. **PC-00**：读取旧接口、实体模型/鉴权、现有HTML/JS/文档，冻结ID与接口契约；不得大范围修改 Gateway/Redis/熔断。
2. **PC-01**：产品登录、侧边导航、顶部状态、工作台真实数据卡/健康节点；创建可访问的 `/console/`。
3. **PC-02**：服务、API、路由列表+搜索/状态+新建/编辑完整表单；不用JSON；保存提示草稿。
