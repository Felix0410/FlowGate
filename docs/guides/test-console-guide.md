# FlowGate 业务前端完整使用手册

本手册按当前页面实际能力编写。每个示例都说明前提、填写内容、按钮顺序、预期结果与恢复方法；示例不是已经替你创建的数据。请先走第2节，之后按需要抽查，不必把所有故障演示都执行一遍。

页面入口：http://127.0.0.1:8081/test-console/ 。完整手册也随Control提供：`/test-console/guide.html`，不依赖GitHub或外网。手册用新标签打开，原业务页面的登录保留；刷新业务页面则需要重新登录。负责人浏览器体验仍待人工确认，自动化检查不能代替该确认。

## 1. 启动、更新页面与登录前准备

如果三个应用已在IDEA运行且数据库正常，不必重新初始化环境，更不要删除数据库或Docker卷。

| 服务 | 本地地址或端口 | 用途 |
|---|---|---|
| Control | 127.0.0.1:8081 | 提供网页、登录、草稿与发布管理 |
| Gateway | 127.0.0.1:8080 | 实际接收业务请求并执行保护规则 |
| Demo | 127.0.0.1:8085 | 提供快速查询、回显、慢请求及可选故障接口 |
| MySQL / Redis | 由本机.env配置，本项目Compose默认13307 / 16380 | 保存目录/历史及会话/速率预算 |

IDEA启动：打开项目根pom.xml并加载Maven；Demo、Control、Gateway三个运行配置的JRE均选17。Control/Gateway的环境文件必须指向FlowGate根目录`.env`，不要误选其他项目的同名文件。这里的密码是你初始化时设置的原始登录密码，不能把BCrypt哈希当作登录密码。

修改前端后，先让IDEA重新构建Control资源，或执行下列构建，再重新运行Control并刷新网页。若仍显示旧版，可强制刷新。编译不会替你重启已经运行的JVM。

```bash
cd /Users/felix/Files/03-Code/Java/FlowGate
source .env
mvn -B -ntp -pl flowgate-control -am package -DskipTests
```

选择脚本启动时，先停止IDEA中的重复应用；选择IDEA启动时，先停止脚本启动的应用。两种启动方式二选一，避免8080/8081/8085端口占用。

```bash
# 只停止之前脚本管理的Java进程，不停止Docker数据服务
python3 scripts/run-local.py stop
# 使用IDEA启动时，只需保留本项目数据库/Redis
source .env
docker compose -f compose.local.yml up -d
# 如果选择脚本启动，则使用下面两条，不再重复点击IDEA运行
python3 scripts/run-local.py start
python3 scripts/run-local.py status
```

只有故障演示需要给Demo的环境添加`FLOWGATE_DEMO_FAULT_ENABLED=true`并重启Demo。正常fast/echo/slow、登录、发布、限速和并发不需要这个开关。不要为了看故障页面而修改密码或内部密钥。

## 2. 第一次只完成这条路线：登录 → 发布公共接口 → 调用成功

1. 打开“环境状态”，Gateway地址保留`http://127.0.0.1:8080`，点“探测服务”。Control、mysql、redis、demo以及Gateway应显示UP；未检查不等于离线，HTTP可访问也不等于所有依赖正常。
2. 打开“账号与调用方”，填本机管理员用户名和原始密码，点“登录”。看到“当前角色ADMIN”后继续；按钮仍灰色时先看角色或会话是否过期。
3. 打开“服务/API与发布”，点“初始化公共Demo草稿”。它只补齐缺失的服务、三个API和路由，不覆盖现有记录，不自动发布。已有数据时返回“已存在”属于正常结果，不要反复手工创建同名对象。
4. 点“当前持久化版本”，让页面自动填写当前发布版本。不要直接填0；本机如果已经发布过，数字可能是5、10或更大。
5. 点“发布完整配置”并确认。展开该按钮下方结果，应看到HTTP200、`PERSISTED`和新版本。例：原版本5，本次保存为6。
6. 点“节点实际应用版本”。找到当前Gateway的节点，默认名为`local-gateway`，确认它的已应用版本也是6且最近上报ONLINE。历史STALE节点可能是以前的实例，不要把历史节点当作当前进程。
7. 打开“接口调用”，编号填`123`、附加文字填`abc`，点“快速查询”。预期HTTP200，展开详情看到`id=123`、`tag=abc`和本次requestId。
8. 点“发送并回显”，合法JSON对象应返回HTTP201。再把模拟耗时设`100`，点“模拟慢请求”，应返回HTTP200。

到这里已经完成一次最小业务闭环。若第7步404，优先回到第6步确认路由已应用，不要通过反复创建Caller或修改密码解决公开接口问题。

<a id="concepts"></a>
## 3. 先理解五个名词，后面就不需要猜

| 名词 | 直白解释 | 例子 |
|---|---|---|
| 服务 | 后面哪一个程序负责处理请求 | 本地Demo程序，地址127.0.0.1:8085 |
| API | 一个接口的方法、入口路径、下游路径和权限要求 | GET /api/demo/fast/{id}，下游/demo/fast/{id} |
| 路由 | 将一个API注册到Gateway的可发布记录 | demo-fast，关联上面那个API |
| 策略 | 对选定对象施加的限速、并发、超时或熔断规则 | demo-slow最多同时处理1个Gateway请求 |
| 草稿 / 发布 / 应用 | 存库待发布 / Control保存新版本 / Gateway实际加载新版本 | 草稿不影响请求，PERSISTED也不等于节点已经应用 |

`{id}`表示一个路径变量，调用时换成`123`；不要把大括号原样带入调用地址。入口路径供用户访问，下游路径由Gateway转发，不能把两者混填。

修改服务、API、路由、策略或启停后，都要“保存草稿 → 读取版本 → 发布 → 确认节点”。Caller凭证签发/吊销则立即作用于会话，不需要发布配置。

## 4. 业务概览：查看有什么，不能据此认定已经上线

先登录，再点“刷新服务与API”。每行显示服务名称、请求方法、入口路径、公开/需授权，以及草稿启用状态。

“草稿启用”只说明数据库目录记录启用，不代表Gateway正在使用它。请同时看顶部已发布版本和当前节点已应用版本。尚无API时按第2节初始化；“刷新”不会创建或发布任何记录。

## 5. 环境状态：如何看探测结果

| 项目 | 看到什么可以继续 | 异常时先处理什么 |
|---|---|---|
| Control | UP | 没有响应时检查8081与Control启动日志 |
| mysql | UP | 检查本项目MySQL容器、连接端口和已初始化账号；不删卷 |
| redis | UP | 检查Redis容器、端口和密码；会话与限速都依赖它 |
| demo | UP | 检查Demo是否在8085运行 |
| Gateway | status=UP | 检查8080、Gateway启动日志及Control同步配置 |

Gateway地址只接受页面当前支持的`http://127.0.0.1:端口`，通常不用改。请用127.0.0.1的网页入口；改用localhost或其他端口可能与允许的本地CORS来源不一致。

“探测服务”不登录也能使用，点击只读取状态。恢复依赖后再次点击，不会自动把以前失败的结果变成UP。

<a id="requests"></a>
## 6. 接口调用：字段和每个按钮的用法

前提：第2节公共Demo已经发布，当前节点已应用。如果你已经给对应路由启用了策略，200/201可能被429、503或504替代，应根据错误code判断，不能一概认定代理坏了。

| 字段/按钮 | 填写示例或作用 | 预期结果 |
|---|---|---|
| 快速查询编号 | 123，替换入口路径中的{id} | 返回相同id |
| 附加文字 | abc，可改成中文 | 返回相同tag |
| 快速查询（GET fast） | 发往/api/demo/fast/123?tag=abc | HTTP200，Body含id/tag/requestId |
| 要回显的JSON对象 | {"name":"flowgate","count":1} | 必须是对象，用双引号；不要填数组、单引号或尾逗号 |
| 自定义演示标记 | hello | 通过X-Demo-Header转发，返回demoHeader=hello |
| 发送并回显（POST echo） | 发送上面的对象与标记 | HTTP201，Body中的body与提交对象一致 |
| 模拟耗时 | 100表示100毫秒，1000表示1秒；允许0..2000 | 越界2001或负数为400 |
| 模拟慢请求（GET slow） | 在下游受控等待 | 无更小保护超时时为200；设200ms超时后请求500ms可为504 |
| 读取网关指标 | 读取已有代理请求的聚合统计 | 不是发业务请求；无样本时可能尚未注册该指标，先完成一次代理请求再读 |
| Caller Token | 私有接口专用凭证，不是管理员登录Token | 公开fast/echo/slow不需要填写 |
| 自定义/私有GET路径 | /api/private/fast/123 | 先按第7节创建并发布私有Demo |
| 发送自定义/私有GET请求 | 使用当前Caller Token调用该路径 | 无Token401，Scope不符403，正确时200 |
| 清空Caller凭证 | 只清空当前页面输入 | 不会在服务端吊销凭证；真正吊销用第7节按钮 |

每项操作下方都有结果，可展开查看实际URL、HTTP、耗时、requestId和Body。requestId每次由网关生成，不要期待它固定不变。发送Echo时不要把真实密码或Token当业务示例放入Body。

<a id="identity"></a>
## 7. 账号、Caller与私有接口：管理员和调用方不是一回事

管理员登录用于管理目录与发布；Caller是使用私有业务API的调用方。两种Token不能混用。管理员会话默认30分钟，Caller凭证默认1小时，实际有效期看签发响应；刷新页面会清空内存凭证。

| 当前角色 | 可做的事情 |
|---|---|
| VIEWER | 读取目录、发布记录、节点和审计，不能保存/发布/创建Caller |
| OPERATOR | 可保存目录、绑定策略、发布和回滚，不能管理Caller |
| ADMIN | 包含写操作，并可创建/吊销Caller |

### 7.1 一次成功的私有接口调用

1. 管理员登录后，在“服务/API与发布”点“添加私有Demo草稿”，再发布并确认节点应用。
2. 在“接口调用”清空Caller凭证，请求默认私有路径，预期401。这说明入口已存在且正在要求凭证；404则先检查路由是否发布。
3. 在“账号与调用方”填Caller名称`guide-reader-01`，Scopes填`demo:read`，点“创建Caller”并确认。名称必须唯一，重做时换名称。
4. 成功HTTP201后，页面自动把返回Token填到“最近一次Caller Token”和“接口调用”的Caller Token，并填写吊销ID。这里不需要手工复制Token到其他地方。
5. 回到“接口调用”，再次请求私有路径，预期200。
6. 若要抽查权限不足，用另一唯一名称创建Scopes为`other:read`的Caller，页面换用新Token后请求同一路径，预期403。

### 7.2 显示、清空和吊销的区别

“显示/隐藏”只切换当前Token是否可见；它不能找回刷新前已丢失的Token。当前页面没有Caller列表、旧Token查询或重新签发入口，不要假设能够从历史响应恢复明文凭证。

吊销时核对“吊销Caller ID”是要处理的数字ID，点击“吊销”并确认。当前凭证立即失效，正常返回HTTP204且无Body；再请求私有路径为401。若吊销的是别人的测试Caller，当前页面也会清空本地Caller输入，请先核对ID。

管理员“退出并清空凭证”会注销本次管理会话并清空页面凭证。不要把Token贴进URL、聊天、Git或截图。

<a id="catalog"></a>
## 8. 服务/API与路由：不用JSON创建一个自定义公开入口

快速抽查优先使用“初始化公共Demo草稿”；下列步骤用于理解并创建自定义入口，不会替换现有公共Demo。

### 8.1 业务表单字段

| 目录模板 | 哪些字段生效 | 当前表单实际保存的内容 |
|---|---|---|
| 服务 | 代码/路由标识 | 创建服务，名称与代码相同，上游固定为本地Demo http://127.0.0.1:8085，启用 |
| API | 关联服务、请求方法、公开路径、上游路径 | 创建公开API并启用；代码字段不参与API保存 |
| 路由 | 代码/路由标识、关联API | 代码作为稳定routeId，优先级默认0并启用；方法/路径来自关联API，不重复设置 |

先点“读取可选服务与API”更新下拉选项。服务没有父级，API选择服务，路由选择API。创建API后，要再次读取选项，路由下拉中才会出现新API。

### 8.2 完整填写示例

1. 如果已有`demo`服务，直接使用它；不必再创建同名服务。要练习创建服务，可选“服务”，代码填`guide-demo`，保存，预期201。
2. 点“读取可选服务与API”，模板选“API”，关联服务选择刚创建的guide-demo（或你确定的现有Demo服务）。
3. 请求方法选GET；公开路径填`/api/guide/fast/{id}`；上游路径填`/demo/fast/{id}`；点“保存业务草稿”，预期201。这里不要填写完整http地址或Query。
4. 再点“读取可选服务与API”，模板选“路由”，代码填`guide-fast`；关联API选择`GET /api/guide/fast/{id}`；保存，预期201。
5. 按第9节发布并确认节点。仅有服务/API而没创建路由时，这个入口不会被代理。
6. 在“接口调用”的“自定义/私有GET路径”字段填`/api/guide/fast/123`，清空Caller凭证，点“发送自定义/私有GET请求”。该按钮按填写的/api/路径发送GET，不限于内置私有Demo；此示例是公开API，无需Caller，应为200。

service代码和routeId必须唯一，重做请先查看已有目录。routeId仅字母、数字、下划线或横线。路径不能用`*`、`**`、正则、编码斜杠；不同路由的同方法路径也不能重叠，例如同时发布`/api/x/{id}`与`/api/x/fixed`会被拒绝。

当前简易表单只创建公开、启用的记录；修改、停用、私有API和自定义字段用下面的高级编辑，或使用“添加私有Demo草稿”。页面没有目录删除按钮，不要按存在删除功能来操作。

### 8.3 高级JSON：只在确实需要修改已有记录时使用

展开“高级JSON编辑”。先选目录并点“查询目录”，从实际结果取得要修改的数字id；不要把routeId字符串当数字id。

| 目录值 | 完整JSON字段 | 更新方式 |
|---|---|---|
| services | code、name、upstreamUri、enabled | 更新ID填该服务的数字id |
| apis | serviceId、method、publicPath、upstreamPath、isPublic、requiredScope、enabled | 私有API必须isPublic=false并填写合法requiredScope |
| routes | apiId、routeId、priority、enabled | 停用路由可将enabled改false |
| policies | code、type、scope、parametersJson、enabled | 参数JSON本身是字符串，普通策略优先用专用表单 |

复制查询结果中的业务字段，**去掉id**后放入“完整JSON”；数字id单独填在“更新ID”。创建时更新ID留空，更新时必须填写。它是完整替换式更新，不是只发一个enabled字段的局部修改。

```json
{"apiId":12,"routeId":"guide-fast","priority":0,"enabled":false}
```

上面的12只是数字结构示例，必须换成你查询到的真实API ID；更新ID应填写这条路由自己的数字ID。保存后还需发布。不要只停用父服务而保留启用子路由，否则发布会因关系不完整而400。

<a id="publish"></a>
## 9. 发布、节点、历史和回滚：每个按钮做什么

| 按钮/字段 | 作用 | 正确使用方式 |
|---|---|---|
| 当前持久化版本 | 读取Control已保存的最新发布版本 | 发布前点一次，自动填写当前发布版本字段 |
| 当前发布版本 / expectedVersion | 防止覆盖其他管理员新发布的配置 | 例当前为5，就提交5；正常不手工猜数字 |
| 发布完整配置 | 发布全部当前草稿，而不是只发布刚编辑的一条 | 检查草稿后确认；成功200且新版本大于旧版 |
| 节点实际应用版本 | 读取Gateway最近应用反馈 | 当前节点appliedVersion等于发布版本才算加载；ONLINE代表近期上报 |
| 发布历史 | 列出已保存版本及回滚来源 | 在展开的结果中查看version；它不是可点击的版本下拉 |
| 回滚来源版本 | 填想恢复的历史version | 必须从真实发布历史选择，不能盲填默认1 |
| 回滚为更大新版本 | 复制所选历史内容发布为新版本 | 旧版本保持不变，版本号继续增大；需再次确认节点 |

### 9.1 遇到409怎么办

先看code：VERSION_CONFLICT表示expectedVersion过期；CONFLICT还可能是重复服务代码、routeId、Caller名称或策略代码。版本冲突时重新读取当前版本、检查草稿，再由你决定发布；重复名称要编辑已有记录或换唯一名称，反复刷新版本不会解决重复名称。

### 9.2 安全回滚一次

1. 查询当前版本和历史，记录当前数字及准备恢复的历史数字。先确认该历史包含你仍需要的公共API。
2. 回滚来源填历史版本；当前发布版本先自动读取；点“回滚为更大新版本”并确认。
3. 如果当前10、来源6，成功会生成11，不是把当前版本降回6。等待当前节点已应用11。
4. 调用一个该历史确定包含的入口，检查实际响应。只有来源历史确实没有私有API时，私有路径才会404；不能笼统地说“回滚V1一定删除私有路由”。
5. 回滚不撤销数据库草稿。下一次“发布完整配置”会重新发布现有草稿，可能把刚回滚掉的入口或策略重新带回来；发布前务必检查。

新发布的策略才按本轮能力执行。历史PENDING策略不会因为升级或回滚自动变为已治理。Gateway重启后熔断运行状态可能重新统计，不能把配置回滚当成保留所有运行统计。

<a id="traffic"></a>
## 10. 流量策略：每秒速率与同时处理数量

先登录并点“读取策略与目标”。“已有策略”选新建时创建新记录；选已有策略时只修改参数/启停，类型、范围和目标锁定，**不会重新绑定到你脑中想换的另一个目标**。

| 字段 | 含义与例子 |
|---|---|
| 策略代码 | 唯一业务标识，例如guide-slow-rate；不是接口路径或ID |
| RATE_LIMIT | 每秒速率限制；Redis令牌桶，可跨Gateway共享 |
| capacity | 桶最多存几个请求额度；例2表示满桶时可短时通过约2次 |
| refillPerSecond | 每秒补回几个额度；例1表示耗尽后每秒补约1个 |
| CONCURRENCY | 限制当前Gateway同时尚未结束的请求数，不是每秒次数 |
| maxConcurrent | 例1表示该目标在本实例最多1个在途请求；只对CONCURRENCY生效 |
| 范围ROUTE | 单条路由，首次抽查推荐；目标选demo-slow |
| 范围SERVICE | 整个服务；CONCURRENCY也支持，但会影响它所有关联路由 |
| 范围API / GLOBAL / CALLER | 速率分别按API、全局、已认证Caller；并发不支持这三个范围 |
| 绑定目标 | 使用已读取的实际对象，不填URL；GLOBAL自动为共享预算，CALLER会询问真实数字Caller ID |
| 启用 | 停用后保存并发布，规则才不再执行；仅在下拉改选还没保存没有效果 |

数值必须是1..1000000整数。不要为了试验随意添加GLOBAL或SERVICE策略，它们可能影响其他API。同一类型、范围、目标只能有一条启用策略，否则发布400；已有同类规则时优先编辑，不要重复新建。

### 10.1 抽查速率限制

1. 确认demo-slow没有其他会干扰此次演示的路由级超时/并发规则；只检查你自己的演示策略，不要擅自停用他人的全局规则。
2. 新建代码`guide-slow-rate`，类型RATE_LIMIT，范围ROUTE，目标demo-slow，capacity=2、refillPerSecond=1，启用，保存并绑定草稿。
3. 按第9节发布并确认节点。回到流量策略，小测试路径填`/api/demo/slow?delayMs=0`，请求数6，点“执行有界并发请求”。
4. 预期能观察到HTTP429 RATE_LIMITED。具体通过几个与桶原余额、发送时刻、补充和其他客户端有关，不保证永远恰好2个通过。
5. 展开各请求结果看429与规则代码，批次最后的success/rejected只是HTTP成功与非成功汇总，**rejected并不专指限速**。读“准入计数”可看聚合指标，不能把所有503也当429。
6. 结束后选择这条已有策略，启用选“停用”，保存并发布，再调用接口检查恢复。等待时间会补充额度，不会自动删除策略。

### 10.2 抽查并发保护

1. 将上面的演示速率策略停用并发布，避免429覆盖并发结果；如有200ms超时，先调整你自己的演示超时策略，否则慢请求会变成504。
2. 新建唯一代码`guide-slow-inflight`，类型CONCURRENCY，范围ROUTE，目标demo-slow，maxConcurrent=1，保存、发布并确认节点。
3. 小测试路径填`/api/demo/slow?delayMs=1000`，请求数6，执行有界并发。预期看到503 CONCURRENCY_LIMITED和正常完成的请求；它不是熔断或数据库故障。
4. 本批完成后单独发送一次slow=0，应恢复准入。结束后停用本演示策略并发布，避免影响后续超时/熔断抽查。

先检查速率再检查并发，后层拒绝不会退还前层已扣额度。本机并发上限不是多台Gateway共享总容量；Gateway超时后释放许可，也不代表下游MVC线程已经被强制中断。

### 10.3 高级绑定与审计

“高级：为已知策略增加绑定”仅用于**增加**关系，不是移动、替换或删除旧绑定。填写实际Policy数字ID，绑定JSON示例如下；42必须换成目标的数据库数字ID，不是routeId字符串。

```json
{"targetType":"ROUTE","targetId":42}
```

目标类型必须与策略scope一致；GLOBAL的targetId为0。不要对已经绑定的同一对象重复点击。当前页面不能查询、删除或重新定位已有绑定；不确定已有关系时不要靠猜ID操作，可先记录新建时选中的目标并交由开发核对。普通使用直接用策略表单，不需要这一栏。

“查看最近审计”只读取管理操作记录，不保存修改；可核对是谁保存、绑定、发布或回滚。它不是HTTP请求Body日志，也不会提供旧Token。

<a id="protection"></a>
## 11. 故障保护：超时、熔断、不可用提示

先点“读取路由与保护策略”，选择目标路由；已有策略只改参数/启停，绑定保持不变。普通表单只创建ROUTE范围保护规则。保存保护草稿、发布配置、查看节点与熔断状态这三个按钮必须依次使用。

### 11.1 响应超时：只填一个等待时间

目标选demo-slow，名称`guide-slow-timeout`，保护类型“响应超时”，最长等待时间200毫秒，启用；保存、发布、查看节点确认。

展开“抽查演示”，点“请求slow 500ms”，预期504 UPSTREAM_TIMEOUT；回到接口调用，slow=0或100预期200。如果返回503，先看code是否仍有并发规则或熔断；如果200，先看节点是否应用新版本。

timeoutMs范围50..10000ms。多个SERVICE/API/ROUTE超时取最小值；未绑定则保持Gateway原全局超时行为。结束后停用自己的演示超时并发布，避免影响并发例子。

### 11.2 初始化故障接口：先开Demo开关，再创建和发布路由

1. 只在本机Demo运行环境设置`FLOWGATE_DEMO_FAULT_ENABLED=true`并重启Demo；给Control/Gateway设置而不给Demo设置没有作用。
2. 在故障保护页点“添加故障演示API草稿”。它只补缺失的公共Demo及GET /api/demo/fault映射，不自动发布，也不替你修改环境文件或重启进程。
3. 发布并确认节点，再展开演示区，接口路径保留`/api/demo/fault`，不要加?mode=，按钮会自动附加模式。
4. 无熔断/更小超时时，“正常请求”为200；“上游故障500”为500；“上游不可用503”为下游503；“上游延迟2秒”正常等待后200，若已有超时则可能504。

若正常请求404：检查Demo开关、故障路由是否发布、节点版本；不要把未开启接口误认为熔断生效。

### 11.3 熔断表单的四个数字是什么意思

| 字段 | 示例 | 含义 |
|---|---|---|
| 失败比例阈值 | 50 | 统计窗口内失败比例达到50%才考虑打开 |
| 最近请求窗口 | 10 | 统计最近10次，允许2..100次 |
| 最少统计请求 | 5 | 至少收集5次才按比例判断，允许1..窗口大小 |
| 熔断后等待 | 3000 | 打开后约等3秒转半开，允许500..60000毫秒 |
| 不可用时响应NONE | 保留故障状态 | 上游失败保留500/503等状态；OPEN返回503 CIRCUIT_OPEN |
| 不可用时响应STATIC_JSON | 只读GET的不可用提示 | 故障/短路返回503 DEGRADED，不返回假业务成功 |

新建名称`guide-fault-cb`，目标demo-fault，类型故障熔断，填上表示例，先选NONE。保存、发布并确认节点。

1. 先发正常请求200，确认该入口可用。
2. 连续点“上游故障500”若干次，达到最少样本量和失败比例后，再请求会出现503 CIRCUIT_OPEN。因为之前的正常请求也占样本，不能断言第5次必然打开。
3. 点“查看节点与熔断状态”，以实际上报的OPEN为准。OPEN时点正常请求仍可能503，这是保护拒绝，不是在说mode=ok写错。
4. 停止发送故障，等待至少配置的3000ms，刷新状态，看到HALF_OPEN后发送两次正常请求，再刷新，应恢复CLOSED。连续试探过快/过多可能被限制；半开任一次失败会重新OPEN。
5. 查看保护计数可读聚合事件；页面状态有上报延迟，STALE说明数据过期，不要根据按钮次数推测状态。

### 11.4 GET静态不可用提示与结束恢复

编辑已有guide-fault-cb，响应选STATIC_JSON，保存、发布并确认；触发故障后预期503、code=DEGRADED、degraded=true、source=GATEWAY_FALLBACK。它不等于200成功，也不用于POST echo；POST启用此模式会在发布时400。

401/403、速率429、并发503、Redis故障503发生在熔断前，不会被这一设置变成成功。OPEN不会访问下游；无降级的上游5xx可返回UPSTREAM_ERROR/source=DOWNSTREAM来区分，原错误Body不保证原样保留。

结束演示时，把自己的故障熔断策略停用并保存、发布；或停止注入故障，等待半开并发两次正常请求恢复。改参数会使用新规则实例，无关发布不会自动清空旧熔断状态；重启Gateway后运行统计可能重置。不要把重启当作日常恢复步骤。

## 12. 操作结果、指标与最近操作在哪里看

每个按钮的结果在当前页面下方，以HTTP状态、中文说明和耗时概括；展开详情看请求URL、Body和requestId。同一操作再次执行会更新该操作的结果，别的按钮有独立结果卡。最近操作只保留当前页面内存中的10条摘要，刷新清空，不是永久审计。

“读取网关指标”看代理请求聚合；“读取准入计数”看限速/并发；“查看保护计数”看超时/熔断/降级。指标是整个进程累积值，可能含之前操作；没有样本时指标可能尚不存在，先执行对应真实请求再读。不能用指标HTTP200代替业务接口成功。

遇到问题，记录页面名称、按钮、HTTP、code、requestId、当前发布版本和当前节点版本即可；不要发送密码、Token或整个.env。

## 13. 常见问题：看到什么，下一步做什么

| 现象 | 判断 | 下一步 |
|---|---|---|
| 按钮灰色 | 未登录、会话过期、角色不允许，或操作执行中 | 看当前角色；需要写权限用OPERATOR/ADMIN，Caller管理必须ADMIN |
| 下拉列表空 | 还没读取，或服务/API/路由尚不存在 | 点对应“读取”；创建API后再读取，才能选它创建路由 |
| 页面旧、看不到完整说明 | 旧静态资源仍在Control进程或浏览器缓存中 | 按第1节更新Control资源、重启并强制刷新；业务页面刷新后重新登录 |
| Failed to fetch / 网络错误 | 服务地址、端口、CORS或服务未启动 | 使用127.0.0.1:8081入口和127.0.0.1:8080网关，先探测，不先改密码 |
| 400 VALIDATION_ERROR | 数字范围、路径、绑定关系、私有Scope或GET降级限制不合法 | 对照当前字段与本手册；完整JSON更新必须包含全部业务字段 |
| 401 LOGIN_REQUIRED / INVALID_CALLER | 管理会话或Caller缺失/过期/用途不对 | 管理操作重新登录；私有请求填有效Caller，不能用管理Token |
| 403 FORBIDDEN / INSUFFICIENT_SCOPE | 管理角色或Caller权限不足 | 分清管理角色与业务Scope；demo私有接口需要demo:read |
| 404 业务接口 | 路由未发布、节点未应用、路径不对或故障开关未开 | 看当前节点版本；故障API另检查Demo开关；不要只看草稿列表 |
| 404 指标 | 指标名称尚未注册或没有该能力样本 | 先运行对应真实业务/拒绝请求，再读取指标 |
| 409 VERSION_CONFLICT | expectedVersion过期 | 重新读取版本并检查草稿，再决定是否发布；不自动覆盖 |
| 409 CONFLICT | 名称/routeId/唯一键可能重复 | 查询已有记录并编辑，或换唯一代码；不是所有409都靠刷新版本解决 |
| 429 RATE_LIMITED | 速率预算耗尽 | 看policyCode，等额度补充或按需修改自己的规则并发布 |
| 503 CONCURRENCY_LIMITED | 当前实例在途许可满 | 等前请求结束；区分并发上限和每秒速率 |
| 503 ADMISSION_UNAVAILABLE / AUTH_UNAVAILABLE | Redis不可用 | 恢复对应依赖后重试，不会自动放行 |
| 503 CIRCUIT_OPEN | 断路器暂不允许，含半开试探许可用尽 | 停止故障、等待并按两次正常试探恢复，查看真实状态 |
| 503 DEGRADED | GET明确的不可用提示 | 检查熔断/故障来源，不当成业务成功 |
| 503 UPSTREAM_ERROR / source=DOWNSTREAM | 下游真实返回不可用 | 与网关并发拒绝/OPEN区分，查看故障模式或下游 |
| 504 UPSTREAM_TIMEOUT | 网关等待下游超时 | 比较delayMs与生效timeoutMs；正常快速请求是否也受其他规则影响 |

## 14. 建议抽查顺序与结束检查

第一次只做第2节公开调用，然后按兴趣依次抽查私有授权、速率、并发、超时、熔断。各组之间先恢复自己的演示策略并发布，避免同时启用多个规则导致结果相互遮盖。

结束前确认：你创建的演示策略是否仍启用；当前节点是否应用最新版本；Caller是否需要吊销；不要误认为关闭网页会删除规则。退出只清除会话，发布配置仍保留，Docker数据不会因网页关闭而清空。

当前能力边界：没有目录删除、绑定删除/迁移、Caller列表/旧Token找回、前端自动重启服务、前端修改.env或生产管理能力。高级入口不是自动补全工具；不知道ID/关系时先查看真实目录，不要猜。正式压测和长期故障实验在脚本与后续验收中进行，不要求用户为了使用页面先运行所有测试。
