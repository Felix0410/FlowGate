先做人工业务验收

  1. 从 首次成功调用指南 进入，完成环境检查、管理员登录、Demo初始化、版本发布和节点确认。
  2. 按说明调用 fast（200）、echo（201）、slow（200），再验证Caller的401/403/200和回滚。
  3. 设置速率/并发规则，观察真实429或503；查看成功请求、Demo实际到达与策略版本。
  4. 按 业务手册 测试 TIMEOUT 504、熔断短路503、GET降级503 DEGRADED及恢复。
  5. 在桌面与窄屏下检查输入、帮助、按钮权限和键盘Tab；把失败项发回Block4分支修复。

三组真实性能对照

模式链路看什么
A · DIRECT客户端 → Demo直接访问时真实业务成功数和尾延迟
B · PROXY客户端 → Gateway → Demo纯代理的附加成本
C · GOVERNED客户端 → Gateway（限速/并发）→ Demoslow被限速后，fast成功吞吐和尾延迟是否改善

所有组使用相同的发送节奏、共享资源和受控数据。HTTP 429/503不是成功请求，客户端自身未发出的请求也不能算Gateway拒绝。单机本地结论不等同生产能力。

source .env
mvn -B -ntp -pl flowgate-control,flowgate-gateway,flowgate-demo -am package
python3 scripts/test-block4-performance.py
python3 scripts/block4-performance.py --seconds 30 --warmup 3 --repeats 2 --output .local/acceptance/block4-performance-run1.json

上面是供本地终端执行的命令，页面本身不会执行这些命令。脚本只在本次创建的隔离MySQL/Redis及双Gateway环境中运行；原始结果保留在本机受限目录，不会自动上传。
